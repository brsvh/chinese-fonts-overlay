# daisyUI Component Index

Choose components by the required behavior and layout. For a named component,
read its guide directly. Compare multiple candidates only when the choice is
unclear; these categories are navigation aids rather than usage restrictions.

Each guide lists classes, markup, and component-specific constraints. Keep the
existing rendering and event system when adapting its examples. CSS classes do
not supply accessible names, native selection state, or a keyboard protocol.
Keep the guide's actual controls and labels when adapting markup, give repeated
instances unique IDs, and update visible and accessible state together. Use a
live region for meaningful asynchronous feedback, not every animation frame or
timer tick.
